# 维护指南

本文件面向项目维护者，补充数据行为、发布流程与现有运维边界。项目介绍和启动方式见 [README](../README.md)。

## 数据加载与缓存

- 单次请求超时为 30 秒，最多尝试三次；鉴权与业务错误直接失败。
- 分页以服务端 `total` 为准，检查重复页和缺失页，避免用不完整数据替换页面。
- 总览的四个数据集全部成功后才更新快照；失败时保留已有数据，并显示异常或缓存状态。
- 登录版不持久化 QMS 记录快照或工厂列表；网络失败时保留当前页面的有效内存数据。原静态预览缓存仍按工厂、版本及 30 分钟有效期校验，不用于正式账号站。
- 工厂、月份和趋势请求使用序列校验，过期响应不得覆盖当前选择。
- 统一调度器约每 10 秒查询待检与超时任务，约每 30 秒加载本月及上月统计。快速轮询只请求状态为 `0` 和 `2` 的任务，并更新当前任务列表、检验员待检统计及预警；统计到期时执行一次完整刷新，不再叠加快速请求。
- 12 个月历史趋势按工厂和当前月份复用 5 分钟快照；当前及上月的趋势点随完整统计刷新。手动刷新会使历史快照过期，切换工厂和跨月不会复用旧范围快照。
- 当前集成未使用 QMS 更新时间游标或事件推送，10 秒轮询属于近实时刷新。真正的事件推送需先确认 QMS 提供 Webhook、SSE 或 WebSocket，再由服务端转发给页面；不要仅提高完整历史查询频率。
- 页面隐藏时暂停自动轮询，切回前台后按过期时间补取。请求执行期间不会叠加自动请求，失败后至少间隔 10 秒再尝试；月度失败不会持续阻塞快速任务查询，已有有效快照保留。刷新间隔会随请求耗时和重试延长。

## 业务统计口径

现有代码保留以下统计规则，维护时应先与 QMS 官方业务口径对账，避免仅根据字段名称统一算法。

| 项目 | 当前行为 |
| --- | --- |
| 主要合格率 KPI | 合格批次 / 已判定批次；已判定批次包括合格、退货和特采 |
| 部分供应商排名图 | （全部批次 − 退货 − 特采）/ 全部批次；进行中的批次包含在分母中 |
| 季度 / 年度筛选 | 滚动 3 个月 / 12 个月 |
| Pareto / DPPM | 上游缺少所需字段时显示空状态 |

大工厂跨季度、跨年度查询仍需拉取明细，耗时受数据量与上游响应速度影响。服务器端汇总能力及 Worker 访问控制策略应单独评估。

## 大屏维护

供应商大屏使用视口高度分配布局行，下方三张卡片等高，风险列表在区域内部滚动。修改布局时，应同时验证空数据、少量数据和大量风险记录，避免恢复为由内容决定页面高度。

图表空状态统一通过 `setSbChartMessage` 显示，先销毁并移除旧实例，再替换提示节点；不要覆盖画布后继续调用旧实例。`ensureSbChart` 会检查实例、宿主和渲染根节点是否仍有效。容器尺寸由共享 ResizeObserver 监听并合并到下一动画帧，隐藏图表在重新显示后恢复尺寸。排名回归必须覆盖“有数据 → 空数据 → 有数据”、正倒排序切换、失效画布以及隐藏后的尺寸恢复；“没有不合格批次”与“没有供应商数据”须分别表达。

来料大屏按全部筛选任务连续循环，末条接回首条，页面配置速度为 48 像素/秒，不显示分页或行分隔线。仅渲染视口所需行数与两行缓冲，初始化及尺寸变化时测量实际行高，通过 `tbody` 的亚像素位移滚动；跨行时更新可见窗口，避免逐帧读取布局。定时刷新按当前单号保留滚动位置，筛选或排序时重新开始。悬停与页面隐藏时暂停，退出时清理监听器与动画任务；系统启用“减少动态效果”时停止自动滚动，提供完整列表供手动查看。普通质量总览仍保留每页 20 条的手动分页。

导航仅保留质量总览和供应商质量，旧 `#tasks` 地址重定向到质量总览。语言选项集中在右下角设置面板，使用原生 Popover API，支持大屏全屏环境。选择选项后保持展开，点击外部、关闭按钮或按 Escape 后收起。

界面恢复原始浅色配色，不加载额外主题样式和脚本；旧 iqc_theme、iqc_transparency 偏好不再读取，因此已有浏览器也会恢复原始 UI。语言设置样式独立在 assets/settings.css，由构建和预览白名单提供。

供应商风险列表以 9 像素/秒滚动。供应商大屏固定使用六列指标、上方两列图表、下方三列卡片，避免继承普通页面的堆叠断点；普通供应商页面继续按窗口宽度换行。来料大屏表格按列比例适配视口，普通列表保留横向滚动。来料大屏下方使用三列等宽网格，检验结果、检验员待检统计、供应商排行等高并排，固定在当前屏幕内。检验员使用姓名、数量和水平条形展示，按人数分列并均分可用高度，不设置内部滚动；低高度屏幕压缩统计间距。测试数据包含 7 名检验员，用于验证超过五人的显示与总数。

桌面来料大屏样式集中在 `assets/incoming-wallboard.css`；平板规则集中在其后加载的 `assets/tablet.css`。不要通过全局放大字体或缩放固定宽度画布处理平板裁切。新增资源必须同步更新 index.html、scripts/check.mjs、scripts/build.mjs 和 scripts/serve.mjs 的白名单。清理未使用代码前需检查 HTML、动态模板、事件绑定和测试引用；不删除历史变更记录及现用业务模块。

平板边界：不超过 1320px 时取消页面最小宽度，任务表在卡片内横向滚动；不超过 900px 时使用纵向面板。901–1320px 且高度不超过 700px 时保留并列布局，但允许页面纵向滚动，避免浏览器工具栏或系统缩放挤掉图表。较宽桌面继续使用原有固定屏幕布局。修改后至少用 1280×800、800×1280 和 1024×640 逻辑视口检查两种看板、英泰双语、全部表列、统一任务行高和旋转后的滚动状态；这些是浏览器模拟尺寸，不等于平板的物理分辨率或真机测试结果。

新增界面文案应接入现有翻译机制，覆盖中文、英文、泰文及中泰双语；不得通过替换业务字段值实现界面翻译。

禁止渐变背景，新增页面和控件应沿用原始纯色 UI。两个环形统计图使用 SVG 纯色圆弧，不使用 CSS 渐变；分段长度按实际数量计算，零数据以中性灰环展示。

## 发布流程

飞书私信提醒使用独立 Worker 和独立数据库，不依赖页面打开。配置、去重口径、停止发送、密钥维护和独立发布步骤见 [检验员待检提醒指南](INSPECTOR_REMINDERS.md)。修改提醒逻辑时同时验证新增任务去重、同日再次新增、人员转交、空任务、完整分页、跨工厂隔离、泰国日期切换和不确定发送结果；手动急料通知另验证管理员权限、CSRF、预览变更、重复提交、停用自动提醒后的队列续发及单次数据库调用预算；不得通过真实检验员批量私信替代测试。

1. 在独立分支完成变更并提交 Pull Request。
2. 确认 CI 通过；涉及界面时完成浏览器验证。
3. 合并到 `main`，确认 CI 成功；在 PowerShell 7 或 WSL Ubuntu 执行 `node scripts/build-auth.mjs`。
4. 通过已授权的官方 CLI 执行 `pnpm exec wrangler pages deploy dist-auth --project-name iqc-quality-dashboard --branch main`，再检查生产域名、登录、受保护资源和 QMS 同步状态。

正式站使用 Cloudflare Pages Worker + D1。原 GitHub Pages 发布工作流与 CNAME 文件已移除，避免重新发布未认证入口；`gh-pages` 仅保留旧部署历史。构建产物采用文件白名单，不包含测试入口、维护文档、本地设置或初始化令牌。部署绑定、首次管理员、域名切换和账号恢复见 [账号登录指南](ACCOUNT_LOGIN.md)。

不要仅覆盖 `index.html`，否则可能遗漏或混用其依赖的脚本和样式。

### 版本回退

定位引入问题的提交，在独立分支使用 `git revert` 创建反向提交，经测试和 PR 合并后重新部署。回退合并提交时，应先核对父提交关系，再选择正确的主线父提交。

不使用强制推送、历史覆盖或远程分支删除作为常规发布与回退手段。

## 凭证与环境配置

QMS 认证由独立部署的 Cloudflare Worker 完成，正式站通过内部服务绑定访问它。浏览器仅请求同源 `/api/qms`，不应接收或保存 QMS 登录密码。QMS 代理代码不在本仓库内；本仓库的 `server/worker.mjs` 是账号认证和受保护网关。维护代理时需单独记录服务版本与配置变更。

`.env`、`.dev.vars` 等本地配置已加入忽略规则。不得将账号密码、令牌、真实检验数据导出文件或未脱敏截图提交到仓库。
