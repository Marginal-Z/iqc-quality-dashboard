# Cpk 与仓管通知接入准备

2026-11-27 提出，尚未启用业务功能。本文记录现有接口边界和待确认项，避免把准备工作误认为已经上线。

## Cpk 分析

当前接入 QMS 的工厂字典和检验任务分页接口；前端使用批次结果、状态和任务信息，尚未接入检验项目实测值及规格。合格率、合格批次数量不能代替连续测量数据来计算 Cpk。

需要先确定数据来源：Excel/CSV 导入，或核实并接入 QMS 检验明细接口。最小数据项为工厂、供应商、料号、检验项目、单位、规格上下限、实测值及采样时间；使用子组估计时还需要合理子组标识。

分析必须隔离料号、项目、单位和规格版本，说明标准差估计方法，区分组内能力 Cp/Cpk 与整体绩效 Pp/Ppk，不能混算不同规格或直接把总体标准差命名为组内标准差。对样本不足、零方差、无效值、单边规格及未确认过程稳定性分别处理，避免输出误导性的“无限能力”或无依据的能力结论。

界面可展示能力指标、样本量、均值、标准差、规格分布和时间趋势；沿用现有权限及语言机制，不改变两种看板模式。数据来源和计算方法确认前不发布业务入口。

公式与前提参考：[NIST Process Capability](https://www.itl.nist.gov/div898/handbook/pmc/section1/pmc16.htm)。

## 检验完成后通知仓管

可复用现有云端 Cron、内部 QMS 代理及飞书卡片通道；待检通知的接收者映射不能直接当成仓管映射。

待确认：仓管飞书人员或群及对应工厂；通知全部最终结果还是仅合格结果；QMS 哪个最终流程状态代表真正完成。特采必须依审批状态提示处理，不应自动写“允许入库”。通知只提供提醒，不修改 QMS 或执行仓库放行。

触发条件须同时满足已确认的完成状态和有效最终结果。任务从待检列表消失可能由取消、转交、筛选或异常造成，不能据此发送完成消息；需要明确查询真实最终记录。首次启用建立基线，不向仓管补发全部历史记录；以工厂、单号、接收者及结果版本去重，处理更正、重开、分配变更与网络失败。复用独立持久队列、重试与发送 UUID，网页关闭时仍运行。

验收覆盖：真实完成、仍待审批、任务取消/转交、重复轮询、结果更正、跨工厂隔离、启用基线、停用、缺失映射和飞书未知发送结果。先用合成数据测试，映射确认后再由用户指定接收者进行实际通知验证。
