# Cpk 与仓管通知

2026-11-27 实现。Cpk 页面使用正式账号访问 `/cpk`；仓管通知使用独立配置和队列，只有管理员保存启用、建立基线后才推送。正式飞书成员范围与接收者需另行核验，部署代码不代表已经完成实际通知联调。

## Cpk 分析

数据来自 QMS 合格记录的关键尺寸矩阵 `criticalDimensionJson`。服务端先完整查询所选工厂、料号及送检日期内的合格记录，再检查最终完成状态，读取检验和物料明细并交叉验证工厂、料号及供应商；浏览器不持有 QMS 凭据，也不能直接指定任意明细接口。

已通过当前 QMS 前端发布包和只读请求核实：`documents/getById/{id}` 返回尺寸 JSON、`doneFlag`、`taskKey`、最终结果及 `materialId`；`documentsMaterial/getById/{materialId}` 返回工厂、料号与供应商。尺寸 `header` 定义项目，`data[0]` 定义标准值及正负公差，后续各行是逐件实测值。公差按两个端点计算并取较小/较大值，不执行源系统中的动态表达式。QMS 没有提供单位时明确标记，不从物料名称猜测。

按供应商、项目、单位和完整规格分别分析。同一检验批次作为一个子组，2–10 个完整实测值的子组使用 `R/d₂`，以子组自由度作权重平均，计算 Cp/Cpk；整体样本标准差用于 Pp/Ppk。缺少有效双边规格、存在无效/缺失样本或标准差为零时，不生成相关能力指标；单边规格和超出支持范围的子组不自动套用双边公式。

页面展示指标、样本量、均值、标准差、测量分布及实测顺序趋势，支持现有五种语言模式。小于 50 个样本时标记描述性参考。数据仅包含合格批次，存在选择偏差，不能代表所有来料过程；过程稳定性和正态性未由此功能确认，不自动给出放行或“过程具备能力”的结论。

单次最多读取 20 个合格记录，日期跨度不超过 366 天；记录过多时要求缩小范围，不将第一页伪装成完整分析。服务端设定分页、明细和样本量上限，查询失败时不发布部分结果。没有填写尺寸的合格记录计入缺失批次数，不生成模拟测量值。

公式与前提参考：[NIST Process Capability](https://www.itl.nist.gov/div898/handbook/pmc/section1/pmc16.htm)。

## 检验完成后通知仓管

复用现有云端 Cron、内部 QMS 代理及飞书卡片通道；仓管配置和队列独立于检验员待检映射。管理员在机器人提醒页面配置泰国协创的仓管姓名、当前应用 Open ID 和启用状态，查看基线及发送记录。

通知范围为全部最终结果：合格、特采、退货。中泰双语卡片列出单号、料号、物料、数量、结果和完成日期；合格提示按仓库流程入库，特采提示核实审批及附加条件，退货提示隔离并按质量流程处理。机器人不修改 QMS 或执行仓库放行。

已核实真实完成记录为 `inspectionStatus=1/3`、`taskKey=close`、有效 `doneDate` 和有效最终结果；仓管查询使用已验证的 `doneDateStart/End` 筛选。首次启用或更换接收者先建立基线，不推送当前历史记录。之后按单号及结果/完成日期/数量版本观察变化，生成持久队列；同一版本不会随重复轮询重发。任务从待检列表消失不会触发通知。

查询覆盖自上次成功检查日期往前两天的重叠范围，最低不早于本次启用日期，能够补取检查中断期间的新完成记录。超过回看窗口的历史更正，以及同日重开又以相同结果关闭而未提供版本字段的变化，无法仅凭此列表接口识别，不宣称为事件流。更换机器人应用后需重新保存仓管配置并建立基线。

每分钟最多生成两张各十批的卡片并发送两张，未入队的新记录留待下轮处理。与检验员队列同时运行时预留调用预算；未映射、未验证应用、查询不完整、跨工厂数据和停用配置均不会发送。网络未知结果保留原始卡片和 UUID，仅在飞书去重窗口内重试；过期未知结果标记为 `uncertain`，不自动制造新的发送 ID。

部署前先备份 `iqc-reminders`，执行 `server/reminders/migrations/0003-warehouse-completion.sql`，再发布提醒 Worker 和 Pages。迁移只新增独立表，默认停用，不替换已有凭据、检验员映射或去重记录。新建环境的 `schema.sql` 已包含这些表。

验收覆盖：真实完成、仍待审批、任务取消、重复轮询、结果更正、跨工厂隔离、启用基线、停用、飞书未知发送结果及批量续发。自动测试使用合成数据，真实接收者完成应用范围授权后再验证正式消息。
